# 报告格式

报告语言与稿件一致。中文稿用中文字段名，英文稿用括号中的英文字段名。

## 每位审稿人的报告

```
# 审稿报告 R1（方法与数据）

## 审稿范围
审阅的内容；因缺少材料而无法判断的方面。

## 稿件概述
用两三句话复述研究问题、设计和主要结论（审稿人理解的版本，供作者核对是否被误读）。

## 总体评价
贡献是什么、对谁有用；主要优点 2–3 条。

## 主要问题（Major concerns）

### R1-M1
- 是否阻断（Blocking）：是 / 否
- 维度（Axis）：数据分析
- 论断位置（Claim）：第三部分第 2 段"AI 使用显著影响学习投入"
- 证据位置（Evidence）：表 3；第二部分第（三）节
- 问题（Concern）：……
- 为什么重要（Why it matters）：……
- 怎样算解决（Resolution test）：……

## 次要问题（Minor comments）

### R1-m1
- 位置（Location）：摘要第 3 句
- 问题与建议（Issue and suggestion）：……

## 建议
小修 / 大修 / 退修再审 / 不宜录用（Minor revision / Major revision / Reject and resubmit / Reject），一两句理由。这是模拟审稿的建议，不预测实际结果。
```

**要求**：
- 主要问题一般 3–6 条，按严重程度排序；没有就写"无"。
- 位置写到章节、段落、表或图；只说"文中多处"的，至少举出两处。
- "怎样算解决"是可检验的标准，作者照做后审稿人能判断是否已解决。
- 不重复脚本输出的原文；脚本发现、核实后确实有问题的，写成具体意见。

# 外审模拟综合报告

## 范围与说明
稿件、审稿人设置（几位、各自负责什么、是否在独立的子任务中完成）；本报告是 AI 模拟审稿。

## 共识的优点

## 阻断性问题
每条注明由哪几位审稿人提出；只有一位提出的也列入。
- R1-M1、R2-M2（两位都指出）：……
- R3-M1（R3 提出）：……

## 其他主要问题

## 审稿人的分歧
哪一点上意见不同（包括同一问题的严重程度判断不同、建议的结论不同），各自的理由，建议怎样取舍。

## 一致性与报告规范
脚本发现、核实后确认的问题（数字、样本量、术语、图表编号、统计报告）。
