# 交付前自查

按评审时常看的方面逐项自查；这不是任何基金的官方评分标准，官方评审要求以当年公告为准。需要更完整的评审视角意见（两三位模拟评审、编号的问题和修改清单）时，用 edu-review 的申报书模式。

| 方面 | 自查问题 | 不合格的典型表现 |
|---|---|---|
| 选题 | 读完选题说明，能否一句话复述研究什么问题？问题是否具体到可以研究？ | 题目大而空；核心概念没有界定 |
| 学术史 | 是否说清了已有研究做到哪一步、还缺什么？缺口是否由文献支撑，而不是凭印象断言？ | 罗列文献；"鲜有研究"没有依据 |
| 价值 | 学术价值和应用价值是否各写到具体能推进或解决的问题？ | "具有重要的理论意义和实践意义" |
| 内容与设计 | 目标、板块、重点难点、方法是否一一对应？每个板块是否写了数据从哪里来、怎样分析？ | 方法只写"文献法、问卷法、访谈法" |
| 可行性 | 数据渠道、预研、团队是否支撑研究计划？进度是否与周期相称？ | 计划三年完成全国大样本追踪，没有数据渠道说明 |
| 创新 | 每条创新是否对应学术史中的一个不足？"首次""填补空白"是否有依据？ | 创新点与研究内容无关 |
| 研究基础 | 是否描述前期研究的核心观点，且不出现任何可识别信息？ | 列出论文题目和刊物 |
| 预期成果 | 形式、数量、等级是否与周期和团队能力相称？（全规的预期成果结项时须达到） | 承诺多篇权威期刊论文 |
| 匿名与字数 | `check_proposal.py` 是否报告身份信息或超字数？ | 出现"我校""本人主持的" |
| 文字 | 是否有错别字、前后术语不一致、标题层级混乱？ | 同一概念多个名称 |

自查发现的问题直接改进申报书；需要用户补充的（前期成果的真实情况、数据渠道、合作单位）列在交付说明中。
