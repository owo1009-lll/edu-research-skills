# 完整论文流程

用户要整篇论文时使用，一句普通请求就够。按 SKILL.md 确认一次主线（研究问题、贡献、提纲、关键证据）并列好写作依据表后，下面各步一次做完，不逐节确认。只要一章、一个提纲或局部修改时，保持那个较小的范围。已有的分析结果是写作材料，不等于可以另估新模型；需要新分析时交给 edu-analysis。

## 1. 读材料，找缺口

- 读实际的背景、研究问题、设计、材料与结果，以及必要的文献。
- 会改变研究判断的缺失事实记下来；不受影响的章节照常推进，只就关键缺口提问，一次问清。
- **不编造**：被试、抽样、知情同意与伦理、预注册、假设、程序和结果都不能补写。
- 用公开发表的研究做示范写作时，在文稿首页写明"二次写作示范，原研究为……"，注明原作者，不声称有新数据或复现；用户要拿去投稿时，直接告诉用户这属于抄袭（见共同规则第 6 条）。

## 2. 新写还是修改

**修改**：先保存原稿的论证图和章节提纲（见 [修改原则](foundation.md)），在原稿上修复。保留原稿的语言、理论框架、专业细节和章节关系；改结构要有记录在案的缺陷或用户指示。

**新写**：
- 写作语言跟随目标期刊：投 CSSCI、北大核心写中文，投 SSCI 写英文；无法判断时问一句。
- 组织标题、摘要、关键词和适合该研究的章节。中文实证论文常见结构为：问题提出（引言）—文献综述与研究假设—研究设计—研究结果—讨论—结论与建议；英文为 Introduction—(Literature review)—Method—Results—Discussion—Conclusion。这是新写时的参考，不是改写原稿的替代提纲。
- 各部分的写法：

  | 部分 | 读这里 |
  |---|---|
  | 标题、摘要、关键词 | [摘要与标题](abstract-title.md) |
  | 引言、问题提出 | [引言](introduction.md) |
  | 文献综述、研究假设 | [文献综合](synthesis.md) |
  | 研究设计、研究方法 | [研究方法部分](methods-section.md) |
  | 研究结果 | [分析衔接](analysis-bridge.md)、[图表](figures-and-tables.md) |
  | 讨论 | [定量讨论](quantitative-discussion.md) 或 [定性叙述](qualitative-narrative.md) |
  | 结论、建议、局限 | [结论与建议](conclusion-implications.md) |
  | 理论性论文 | [理论论证](conceptual-argument.md) |

- 写法卡只用于本文论证确实需要的推进步骤。

## 3. 首稿和图表

- 首稿（或修订稿）存到 `edu_output/writing/` 下的新任务文件夹，不覆盖原稿和之前的输出。
- 修改时按 [修改原则](foundation.md) 的三类记录实质改动；改结果表述前先核对"研究方案—稿件—实际分析"三者，保留分析的主次和方法身份，如实报告冲突和实际偏离，不事后补称"预先设定"。
- 图表用实际结果制作，见 [图表](figures-and-tables.md)。普通任务没有数量要求；替换原有图表时，删去冗余或缺乏支撑的要说明理由。模型图和框架图的箭头要区分流程、概念、待检验、已报告关联和候选主题几种关系。

## 4. 引用

读 [引用核验](reference-verification.md)。每条引文的身份都要通过实际访问的权威记录核实；支撑关键论断的段落要实际读过，记下位置、版本和阅读范围。只读过摘要或转引的文献如实限定，不假装读过全文。查能访问到的更正、撤稿和版本信息。来源冲突靠查到的其他来源解决，或删去、收窄论断，不凭记忆。

## 5. 全文评阅一次

首稿和图表保存后，做一次聚焦的全文评阅：

- **前后呼应**：研究问题↔方法↔结果↔讨论与结论；摘要↔正文↔图表。
- **细节**：措辞、数值的单位与比较对象、样本定义、日期与时间顺序、引用、反面证据、重要遗漏。
- **修改稿另查**：对照原文关键段落和章节关系，找被削弱的有据论断、被删的推理、被换成套话的内容、放错位置的限定、混进正文的待办提醒。
- **措辞**：用动词区分效果、理论、设计和实施层面的贡献；方法上的敏感性留在局限部分。
- **跑两个脚本**：
  ```
  python <本skill>/scripts/check_voice.py --draft 首稿.md --source 结果或材料文件
  python <本skill>/scripts/check_consistency.py --draft 首稿.md
  ```
  前者查免责句、散落的局限句和材料里找不到的数字；后者查摘要与正文数字、样本量、同一数值的小数位、构念名称和自称是否前后一致，以及图表编号与引用是否对应。脚本只列线索，逐条回到原文判断。
- 同一上下文里的评阅是自查；在真正独立的上下文中做的称为 AI 评阅，都不是专家或人工验证。用户要投稿前的外审模拟时用 edu-review。

保存评阅记录，修订一次全文，导出和核验中发现的缺陷修到解决为止。任何脚本或 AI 打分都不能单独证明论证忠实于原意。

## 6. 交付

- 默认先给 Word（图表嵌入正文），另附可编辑表格、SVG/PDF 图和绘图代码与数据、简短的待补事项和引用核查表；用户要其他格式照办。做法见 [文件交付](file-delivery.md)。
- 首稿、评阅记录和详细的来源对应另存。内部文件名、日志和开发说明不进入论文正文。

## 7. 期刊格式

- 没有目标期刊时用通用学术格式，不声称符合某刊要求。
- 指定期刊时，排版前先读该刊当期的作者须知，并记录实际采用的格式选择。
- 完成的 Word 稿不代表伦理审批、作者署名、版权许可或投稿条件已经具备。
- 这个流程根据已有证据写论文，不收集数据，也不会自动完成整项研究。
