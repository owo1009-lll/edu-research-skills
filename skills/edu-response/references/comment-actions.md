# 意见分类与处理

## 读编辑信

- 先确定决定类型：小修（minor）、大修（major）、退修再审（reject and resubmit）。编辑点名的意见（"请特别注意审稿人 2 的第 3 点"）列为 E 编号并优先处理。
- 记下编辑提出的格式和期限要求：修改说明的形式、是否需要标红稿、字数上限、截止日期。
- 中文期刊的外审意见常是一段连续文字，按要求逐一拆开；英文期刊的意见多已编号，保留原编号。

## 分类

| category | 典型意见 | 常见处理 |
|---|---|---|
| 选题与贡献 | "创新性不足""与已有研究区别不清" | 在引言和讨论中写清与最接近研究的具体区别，不靠"首次"之类的说法 |
| 理论与文献 | "理论框架与研究问题联系不紧""缺少近三年文献" | 补充核验过的文献，说明理论如何推出假设 |
| 研究设计 | "样本代表性""抽样方式""变量测量" | 补充设计细节；无法改变的写进局限 |
| 数据分析 | "未做共同方法偏差检验""应报告效应量""应控制某变量" | 交给 edu-analysis 实际运行，回复中报告结果 |
| 结果解释 | "结论过度推断""因果表述不当" | 改动词和论断范围 |
| 写作与格式 | "摘要过长""表格不规范""参考文献格式" | 直接修改 |
| 编辑部要求 | "请逐条回复""修改处标红""控制在一万字以内" | 按要求交付，回复中说明在哪里体现 |

`type`：会改变论文判断或需要实质工作的为 major；表述、格式和小的补充为 minor；编辑的程序性要求为 editorial。

## 处理决策

| action | 什么时候用 | 回复要写 |
|---|---|---|
| 采纳 | 意见合理且能做到 | 做了什么、改在哪里、修改后的原文 |
| 部分采纳 | 意见合理，但完全照做会超出数据或设计 | 做了哪一部分、为什么另一部分不做、怎样在稿件中体现这个限制 |
| 说明不改 | 意见基于误读，或照改会使结论失真 | 用稿件内容或文献说明理由，指出相关位置；必要时把原文写得更清楚，避免其他读者同样误读 |
| 待核实 | 是否照做取决于暂时无法核实的事实（如审稿人建议引用的文献查不到） | 回复按两种情况各起草一稿，列入作者待办，核实后保留其一 |

审稿人误读往往说明原文表达不清。即使不改论断，也考虑在原文中补一句澄清，并在回复中说明。

## 难处理的情况

- **要求补收数据或重做实验。**做不了时说明原因（研究周期、伦理审批、样本不可再得），提供可行的替代分析（如敏感性分析、稳健性检验），并把这一点写进局限。不承诺做不到的事。
- **要求的分析与设计不符。**例如横断面数据要求做因果推断：说明设计能支持的推断，改为相应的表述，必要时补充能做的分析。
- **审稿人之间意见冲突。**分别回复各自的意见，在给编辑的信中说明取舍和理由。
- **意见超出本文范围。**说明本文的问题边界，把它作为后续研究方向写进结论，但只用于确实超出范围的意见，不用来推托能做到的修改。
- **意见含糊。**按最合理的理解处理，并在回复中写明"我们将这一意见理解为……，据此做了……"。
- **意见要求引用某些文献。**核验这些文献确实存在、与本文相关后再引；不相关的礼貌说明。按题名、作者、年份都查不到的，不引用，标为待核实并请用户检索，回复中如实说明未能找到。
- **需要用户补材料才能完成。**先完成能完成的部分，缺的地方留编号占位 `【待补①：……】`，与作者待办一一对应；补齐前不提交。

## 修改的连带影响

一处实质修改常牵动其他部分，改完逐项核对：
- 新分析改变了结果 → 摘要、结果、讨论、结论、图表同步；
- 增删变量或样本 → 方法部分的样本描述、描述统计表、样本量；
- 改了术语或构念名称 → 全文统一（用 check_consistency.py 的 `--term-group`）；
- 增删文献 → 参考文献表和编号（GB/T 7714 顺序编码需要重排）。
