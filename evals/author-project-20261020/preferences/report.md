## 实际请求与执行

首次合成请求为：

> 以后修改我英文定性论文的 Discussion 时保留 professional discretion 这样的概念标签，先讲我的判断再给材料；有专业依据的 should 别一律弱化。这个项目存档位置由你在本测试目录内安排。

随后请求：

> 把这一段压缩到55-75英文词，保留关键认识和依据。

助理将第一条请求拆为三条明确作者表达偏好，使用 `author_preferences.py`，以 UTF-8 JSON 标准输入实际保存；每项有 en、qualitative、discussion、revise 筛选及原始授权话语。`load` 返回三条有效项。另建 `project-no-profile`，不传 `--profile`，`load` 返回零条有效项、零条候选，然后完成同一局部改稿请求。

原段只有 49 词，因此“严格缩短”与 55–75 词下限不能同时满足。本次依具体词数范围整理，只增加已提供的样本与制度情境，不称为严格压缩。首稿的 53/54 词失误已分别保留为 `first-draft.md`，通过计数修至 55 词；启用稿又经语义检查，把“24 名教师都描述某做法”的潜在含义改为“访谈样本为 24 人，参与者描述做法”，不编造频次。

执行入口为本目录 `run_forward.py setup`、`run_forward.py manage`、`finish_artifacts.py`、`check_context_wrapper.py` 和 `final_audit.py`。命令使用 Python `-B`，避免在仓库生成字节码。每次实际子进程的完整命令参数、JSON 请求、标准输出和错误都在 `operations.jsonl`；全量保留日志仅因这里是明确授权的合成测试，不应照搬到真实作者偏好场景。

## 逐句语义比较（由 AI 执行）

| 合成要求及证据边界 | 启用稿 | 不启用稿 |
|---|---|---|
| 保留 `professional discretion` 标签 | 首句保留 | 首句保留 |
| 作者判断先于材料 | 判断与专业建议置于首句，第二句接访谈 | 判断首句、访谈第二句，建议第三句 |
| 有专业依据的 should 不一律弱化 | 保留 `administrators should protect time` | 同样保留 |
| 共同课程目标与教学顺序的关系 | 根据学生即时需要调整任务顺序，同时保留共同目标 | 同样保留 |
| 制度约束与实践判断并存 | 末句在制度约束内解释责任协商 | 末句同样体现 |
| 访谈不证明学业效果 | 保留具体的 attainment 边界 | 同样保留 |

`should` 的保留来自合成作者已有的专业判断，不能写成“保护时间已经提高成绩”的实证发现。末句的学业效果边界决定读者怎样理解建议，因此保留它不是任意添加免责。没有添加文献、受访者原话、观察、理论机制或效果数据。

不启用稿也保留概念与 should，是因为原稿及 edu-writing 基础修改规则本来就要求保留有依据的作者判断。不能故意降低对照稿质量来制造偏好收益。两项目磁盘状态独立，但两稿由同一评估代理撰写，该代理见过所有合成请求；没有实现模型上下文盲法。

## 发现、修复和限制

1. **初始管理文档有作用域缺口。** 初读的暂停示例为 `{"action":"update","id":"…","changes":{"status":"paused"}}`。对已存入个人档案的项照此调用，即使传入 `--profile`，仍返回 exit 2：`Preference not found in this authorized store.`。原因是脚本默认项目作用域。加入 `"scope":"author"` 后暂停成功，再恢复成功。最初失败与重试均保留。父代理随后修正文档，明确个人项的所有 update/delete/undo_add 都需 scope=author；本评估代理已重新读取确认该文字。管理结果文件仍保留 20 项记录中的 19 通过和 1 历史失败，不抹去观察。

2. **局部段落检查器的既有边界。** 两份无标题正文各为 55 词，但直接 `check_prose.py --draft final.md` 输出 `Sections found:` 为空以及 `1 words`。标题副本加 `# Discussion` 后正确识别 55 词。原始错误统计和包装副本结果均保留；原稿不加检查标题。此为既有脚本行为，本轮没有修改实现。使用者应显式提供章节上下文或把无识别章节视为未检查，不能把零提示视为通过。

3. **执行者自己的首稿词数错误。** 初稿 53/54 词，不满足下限；已保存首稿、记录修订并按程序复核最终两稿均为 55 词。这不归因于偏好存储脚本。

4. **终端编码。** 最初 Windows PowerShell 默认读取及 Python 终端输出出现乱码显示；随后使用 `Get-Content -Encoding UTF8` 与 `python -X utf8` 读取，确认磁盘 JSON 正确。内部 CLI 请求从开始即使用 UTF-8，不存在偏好内容损坏。

5. **观察范围。** `check_voice` 没有发现未给出的数字，并把末句列为实质区分；`check_prose` 只是表达线索。这里没有真实作者判断、效用指标、计时或盲法质量比较，也没有验证所有并发、损坏输入、跨机器或长期使用情况。当前结论限于本合成案例中的可执行性、明确要求符合度和实际存储边界。
