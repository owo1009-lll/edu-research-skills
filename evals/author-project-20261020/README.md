# 作者偏好与材料关联核对

本轮在 0.13.0、提交 `f3e2066a181cbda90b75bd71296c49a9ac5f6007` 上实现两项功能。设计和复用边界见 [PLAN.md](PLAN.md)。公开材料全部为合成项目，不包含用户私稿、真实个人偏好或新的文献蒸馏。

## 直接使用

- “以后修改我的英文 Discussion，保留概念标签；先讲有依据的判断，再解释。”→ 在用户侧保存相应范围的偏好，后续只加载相关项。
- “你记住了哪些偏好？”“这条只用于当前论文。”“暂停这条。”“撤销刚才记住的偏好。”“删除这条及例句。”→ 查看、改范围、暂停或物理删除记录，不保留隐藏文本历史。
- “这份是我确认的新结果，检查 Word 和 PPT 哪里还没改，先别修改。”→ 检查已指定材料的数值、标签、来源及依赖解释，给出定位和依据。
- “同步修改这些已确认的位置，保留原件。”→ 生成新版本；需要实质判断的地方继续标记。PPT 修改计划后重建并检查真实对象。

这些操作由助理翻译为内部调用，用户无需维护 JSON。偏好与项目事实分开。没有档案时仍能写作，未确认候选不自动改稿，当前明确要求优先。原稿审阅继续默认高亮＋批注，不自动改正文。

## 完整复现

在仓库根目录安装开发依赖后，指定**仓库外的新目录**：

```text
python -m pip install -r requirements-dev.txt
python -X utf8 evals/author-project-20261020/reproduce.py --out <新的示例目录>
```

有 PowerPoint 或 LibreOffice 渲染环境时添加 `--render`。脚本实际创建 Word、结果 JSON、PPT 内容计划、原生 PPTX、项目记录、作者偏好及修改前后核对报告；没有运行统计分析，合成数值不冒充真实分析结果。脚本拒绝覆盖现有输出目录。

归档版见 [example](example/)，另有未参与规则开发的独立试用 [preferences](preferences/report.md) 和 [linked-materials](linked-materials/independent-report.md)。其中 `@RUN@`、`@REPO@`、`@EVAL@` 为公开归档的路径别名，替代开发者绝对路径；存储字节与文本改写的记录见 `archive-manifest.json`。归档是实际运行证据，重新执行应使用上述脚本和新的仓库外目录，不在归档原件上覆盖运行。

完整示例先报告旧值，不改原件；再同步已授权数值；将“区间仍高于零”保留在中间稿并报告为需重新判断；最后按另一个明确合成请求，依据实际上下限修改为“区间包含零”，保存单独的审读稿并再次核对。`paper-updated.docx` 是只同步数值的**中间稿**，完成后的稿件是 `paper-reviewed.docx`；不把中间稿中的旧解释交作终稿。

## 实际观察与修复

| 场景 | 实际表现和边界 |
|---|---|
| 样本390→382、干预组后测18→16、区间0.009 [0.004, 0.014]→0.006 [-0.002, 0.014] | 完整示例发现16处旧值；同步后这些位置一致。总招募410、对照组14保持；区间解释经过单独阅读修正。 |
| 相同数字对应不同统计量／样本／模型 | 回归测试分别保留 r、β、总样本、分析样本、调整前后及敏感性结果；没有全局替换相同数字。 |
| 显示精度与单位 | `.210` 与 `.21` 等价；明确同一比例后才允许百分数换算；舍入掩盖0或1边界进入待判断。 |
| 首次登记新来源，正文已是旧值 | 独立试用最初漏报相关解释：来源没有历史变化，因此依赖未触发。修复为当前不一致同样触发阅读；同一留出材料复测由0处变为7处依赖提示。 |
| 同一段落既有确定旧值又有未决子组 | 独立试用最初错误允许两个70%一起改为65%。失败输出保留；修复后拒绝含未决对应的整段自动同步，明确位置仍可处理。 |
| 引文支撑 | 只接受既有 claims/semantic_review 结构中唯一对应且 supported 的记录；论断扩写进入pending，无关条目更新不会使本条失效。最初接口说明不足已补齐。 |
| 作者偏好管理 | 实际验证范围、任务和语言筛选、未表态拒收、项目停用、暂停恢复、删除与撤销。个人项管理示例原先遗漏scope，真实失败和重试保留，文档已修正。 |
| 启用／不启用偏好的真实文本 | 两稿均保留 professional discretion、有依据的 should 和未检验学业成绩的边界。基础修改规则已能保留这些内容，不能为了制造收益降低对照稿；本比较没有盲法或真人评分。 |
| 原件再编辑与移动 | 指纹变化阻止旧请求修改；唯一完整段落可重定位；标签guard不能可靠迁移时进入待判断。明确改名通过文件ID与内容指纹处理，不扫描目录。 |
| 解析失败 | 可用部分继续完成，Word页眉、未重算公式、损坏附件、扫描PDF等明确未检查。 |

独立试用记录的是全新合成两阶段研究：15处旧数值、不同样本与调整模型、非零参考值、引用扩写、未决子组、授权修改和真实渲染。原稿11份的字节保持检查，以及全部失败与重试，见 [独立报告](linked-materials/independent-report.md)。

## 验收范围

机器测试、原生对象核对、实际渲染和语义阅读分别记录。渲染了修改前后各3页PPT，检查双系列颜色、类别、单位、区间线及标签、样本表；Word通过本机Word导出PDF并检查，未观察到截断或表格错位。实际运行记录与最终代码哈希见 `validation.json`。

本机首次全套测试有一项 R 已知答案检查失败：宿主传入 `C.UTF-8`，Windows R 解析中文路径失败。采用 Windows 支持的 `English_United States.utf8` 后模块测试通过；没有修改统计代码或跳过该项。首次失败保留在验证记录中，最终全套及提交后的CI结论以实际日志为准。

尚未覆盖所有对象：自动同步限普通DOCX正文／表格文字、Markdown/TXT和JSON；CSV/XLSX需按授权另存并复核，PPT通过既有计划重建；域、复杂修订内部、页眉脚注、图像数字、扫描PDF或未重算公式不能宣称已准确同步。语义映射和解释判断依靠实际阅读，脚本通过不证明来源事实正确。未映射内容列出范围，不把零提示视为全文无错。

正常使用不保存完整偏好请求日志。独立评测日志保留的所有偏好和例句都是明确合成测试数据；删除测试证明的是脚本拥有的真实存储项已移除，并不声称清除了外部备份或聊天记录。
