# 逐项验收索引

依据用户本轮完整需求；脚本、材料和阅读判断分开。基线、实施顺序、状态与失败处理见 [计划](PLAN.md)。统计、PPT生成／成品检查器、期刊检索、原稿审阅实现与基线逐路径比较未改动；入口仅增加关联核对路由。

| 要求 | 权威证据与判断 |
|---|---|
| A1 明确表达、真实取舍、示范归属 | author_preferences 的 source 校验；`test_actual_rejection_records_choice_and_reason`、`test_inference_remains_local_candidate`；独立请求与 operations.jsonl。测试请求明确为合成，不冒充真实用户确认。 |
| A2 任务／项目／跨项目授权、候选 | 任务ID和档案隔离；独立一次性材料先行稿、下一任务不加载、项目停用不改个人档案；长期话语直接保存，不二次确认。 |
| A3 来源时间、类型语言章节任务、条件例外状态 | 实际存储项及 schema；来源与创建时间、active/candidate/paused/superseded；事实类别拒绝。个人档案没有24人等项目事实，定义在项目资料。 |
| A4 按需加载、当前要求优先、概念与依据保护 | 实际 enabled/no-profile 两稿、一次性任务稿与冲突记录；候选单列，不进入active。语义冲突由助理读本次要求，脚本不自动判断事实。 |
| A5 查看／修改／暂停／删除／撤销／项目停用 | 20项管理记录及最终存储扫描；保留初始scope说明失败和成功重试；删除短例在当前存储无残留。没有文本历史备份。 |
| A6 轻量、非模型训练 | 两份55词正文及独立实际用户交付；管理细节仅作为公开合成评测归档，不是正常稿件附件。 |
| B1 格式和未检查范围 | complete example + independent materials + readers测试：DOCX、MD、CSV、XLSX、JSON、PPTX/计划、PDF文字；损坏附件、扫描页、公式等明确报告。 |
| B2 最小记录、首次基线、候选文件 | register 的明确files/roles、SHA、稳定位置和读者映射；首次使用不一致触发解释核查但不声称历史变更；无目录扫描。 |
| B3 权威与多种有效结果 | 显式authority；未决子组留待判断；不同样本、调整模型并存；已确认运行需状态及输入／脚本记录，失败后不继续当权威。 |
| B4 语义而非同数匹配 | fact identity + reader理由 + guards；r/β、样本、模型、分析身份的反例；舍入与比例换算的正反例、非零参考值。语义对应不是脚本已证明。 |
| B5 变化传播和解释 | 当前不一致与历史变化均传播到显式依赖；公开例的旧区间句先待判断，再单独授权修正；独立历史案例保留仍成立的谨慎解释。定义、设计、计分等可作为text事实接入同一流程，不要求完整关系图。 |
| B6 作者可行动的定位输出 | independent author-result.md、example 下 check.md/check.json：位置、当前值、新来源、四类判断和建议；详细身份留在内部JSON。 |
| B7 授权副本、歧义隔离、真实图表 | 原件哈希；新的DOCX/MD/计划与PPT；旧报告拒绝、错误新值拒绝、同段未决绑定拒绝；原生check_deck、实际PowerPoint/Word渲染。自动格式外可按授权手工副本处理并复核，不能宣称全格式自动同步。 |
| B8 引用支撑失效 | source/claim/support/相关ledger指纹；初始无效结构不当支持、扩写pending、无关条目不误报；reverify需实际阅读理由。 |
| B9 幂等、身份、旧定位、部分失败 | 同输入报告字节和mtime不变；显式改名保留内容身份；删除/损坏保留失效范围；段落插入后拒绝旧请求；唯一文本可迁移，guard不确定时复核。 |
| 功能配合与不扩展范围 | 偏好与材料存储分离，事实不能变成长程风格；无后台监控／云同步、无批注回复或原生修订开发；edu-review原有默认原稿批注行为通过兼容测试。 |
| 独立新材料 | 两位独立上下文AI代理只读技能和新的合成任务，不读开发测试答案；保存首稿错误、失败、修复建议与复测。没有真人或盲法收益结论。 |
| 公开交付 | README、复现脚本、242项实际合成归档、双语入口、简洁手册、数据与实现哈希及测试记录。隐私档案脚本拒绝写入公开工作树；归档工具仅导出三套明确合成试验。 |

验收不等于全格式和全论文自动理解。新增功能的解释、语义对应和支持判断仍由助理实际阅读；尚未做真人时间测量。完整限制和发现见 [说明](README.md)、两份独立报告；机器与视觉结果见 `validation.json`。最后发布须等待同一提交的 Python、R 两个 GitHub 作业成功。
