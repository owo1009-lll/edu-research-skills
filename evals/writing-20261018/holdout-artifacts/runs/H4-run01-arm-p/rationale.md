# 翻译依据与工作记录

## 任务与范围

依据 H4-request.md，将 H4-materials.md 中 B054—B057 四个连续英文段落译为自然中文。按原段落顺序保留作者的论证、判断力度、条件、案例及括号内举例。材料中的背景只帮助理解，不译入正文。用户已要求直接执行并指定 Markdown 交付；不另作主线确认，不生成 Word。

本任务为已有文本的节选翻译练习，不是新写理论文章，也不是干预效果评价。仅用用户提供的出处与许可信息，不联网核验。署名和许可放在译文之外的来源声明中，说明译文是改编而非作者审定的措辞。

## 动笔前还原的论证

教育问题是：当发言超出群体占主导地位的认识框架时，如何使它获得回应并进入探究。作者先提出引导者必须践行交往互惠这一规范要求，再说明群体沉默有时可能出于犹疑，因而引导者可以有意识地采用已有的追问与澄清做法。随后以 Silver 的案例展示可采取的回应方式，提出拓展概念、质疑主导认识框架所依赖的前提，最后限定这些做法的保护作用并要求持续反思。本文不把这些建议翻译成已获验证的干预效果，不替作者解释群体为何沉默。

| 单元 | 功能 | 原文论点 | 证据或来源 | 翻译处理与理由 |
|---|---|---|---|---|
| 第一段 | 规范要求及实践起点 | 引导者必须将交往互惠作为规范性价值；不能当然期待学生知道怎样回应理解范围之外的立场；沉默有时可能源于犹疑 | B054；原文的 Lardner 引语 | 保留 must、may sometimes 和 could 的差别；不把犹疑写成 Silver 案例的已知原因 |
| 第二段 | 有条件的责任与具体示例 | 共同体未自行回应时，引导者负有示范责任；可以要求阐释，也可以组织寻找反例的即兴练习 | B055；原作者转述的 Silver 案例 | 保留条件句、事后设想、即使不赞同反例的让步及二战举例；take up 不译成赞同或采纳 |
| 第三段 | 从回应推进到概念与框架工作 | 若仍不能使贡献 hearable，可能还需拓展概念或质疑主导框架；发言会获回应的明确预期是先决条件 | B056 | 保留条件性、两项工作的选择关系及 neither…until 的强前提；重点自查 hearable 与 literal level |
| 第四段 | 保护作用、反思要求及结构性视野 | 策略可能通过限制暴力的显现方式降低发生概率，并非万无一失；引导者必须反思；系统进路提供应对不同伤害的指引 | B057；原文提及 Dotson（2014） | 不删原有防护边界，不增添效果证实，不把 systems approach 变成系统综述或万能解决方案 |

## 术语与待核查问题

| 原词 | 首稿用法／计划 | 选择依据及边界 |
|---|---|---|
| epistemic violence | 认识暴力 | 以“认识”维持与认识框架、认识排斥的概念连贯；不将其缩成个体心理认知过程 |
| epistemic frameworks | 认识框架 | 保留 dominant 与 beyond comprehension 的关系条件 |
| epistemic exclusions | 认识排斥 | 原文理论术语，不据本节扩写其分类 |
| structural epistemic harms | 结构性认识伤害 | 保留 structural 与 harms 的范围，不替换成所有结构性不平等 |
| community of inquiry | 探究共同体 | 全文统一 |
| facilitator | 引导者 | 不擅自限定为教师或工作坊主持人 |
| communicative reciprocity | 交往互惠 | 表达回应与接续交流的规范；不等于观点一致 |
| take up / acknowledged and integrated | 回应、接续交流、关注并纳入讨论 | 随句法对象作一致的语义转换，不译成采纳或认同 |
| contribution | 发言 | 本节指参与者提出的见解，不译成学术贡献或研究成果 |
| hearable | 首稿保留“被听见”的隐喻，复核时检查是否需要释义 | 背景显示涉及能否进入理解与回应，而非声音是否被耳朵听到 |
| on a literal level | 首稿“至少在字面层面” | 需核查中文是否误导为字面释义；结合段内“实际回应先于深层拓展”的关系判定 |
| individual integrity | 个体的人格完整性 | 不限缩为诚实或道德操守；这是一项译法选择，并非核实过的通行译名 |
| gun violence / armed struggle | 枪支暴力／武装斗争 | 原文并列时保留两者，不互相替代 |
| systems approach | 系统进路 | 不作系统综述或已验证模型解读 |
