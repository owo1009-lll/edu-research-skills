# 范例讨论与同伴反馈：阶段进展（合成示例）

汇报类型：阶段进展；计划时长：4分钟。

## 1. 合成示例｜我们已完成一次可行性试用

核心信息：研究问题：范例讨论能否帮助师范生提出更具体、可操作的反馈？


图表安排：原生可编辑table；不使用原文图片。

| 事项 | 当前状态 |
| --- | --- |
| 任务与编码规则 | 初稿完成；研究者已共同讨论 |
| 课堂试用 | 一个便利招募班级，12名志愿者 |
| 机制构想 | 共同辨认质量帮助判断；尚未测量 |

图注：已完成的是可行性试用，不是教学效果验证。

来源：合成示例材料 · H3：问题、理论构想与已完成工作
预计：60秒

讲稿：

这是为团队讨论准备的合成阶段示例。我们的核心问题是，在同伴反馈前先讨论范例，能否帮助师范生给出更具体、可操作的建议。理论上，共同辨认作品质量可能帮助判断，但这个机制还没有测量。目前已完成任务设计和反馈编码规则初稿，并在一个便利招募的班级里让十二名志愿者做了一次可行性试用。这个阶段首先要知道任务能否完成、反馈内容呈现哪些特点，然后才决定怎样进入效果验证。两位研究者已经共同讨论规则，但尚未各自独立编码，因此今天也不报告一致性系数。

## 2. 合成示例｜反馈交得出，建议还需支持

核心信息：初步编码：12人均提交；9份定位具体问题；5份给出可操作建议。


图表安排：原生可编辑chart；不使用原文图片。

| 类别 | 试用反馈 |
| --- | --- |
| 提交反馈 | 12 |
| 指出具体位置 | 9 |
| 可操作修改建议 | 5 |

图表单位：份。

图注：分母为12；各项可重叠；未独立双编码；一次试用描述。

来源：合成示例材料 · H3：提交与反馈计数
预计：60秒

讲稿：

先看这一次试用留下的反馈。十二个人都提交了，说明在这次安排下，任务能够实际完成。内容上，九份明确指出了作品中的具体位置，五份提出了可以操作的修改建议。三个条形对应不同维度，可能重叠，不能相加，也不能由这些总数推断是哪五份反馈同时满足了另一个维度。这些计数仍基于编码初稿，下一步需要独立双编码来检验判断是否稳定。当前没有基线、对照班或学习成绩测验，所以我们不能说范例讨论带来了提升。不过，建议这一维度提供了明确的改进焦点，下一页结合观察说明这个焦点。

## 3. 合成示例｜把“发现问题”接到“提出建议”

核心信息：团队决定：保留范例讨论，改进支持学生提出修改建议的提示语。


图表安排：原生可编辑quote；不使用原文图片。

> 不知道如何把问题改成建议

一次试用观察笔记：2名学生提出（合成设定）

图注：具体困难用于改进任务；不作总体比例推断。

来源：合成示例材料 · H3：观察笔记与团队主张
预计：60秒

讲稿：

观察笔记中有两名学生说，不知道如何把问题改成建议。它不是一个可以推广的比例，而是这次试用中直接出现的困难。联系上一页，提交任务已经可行，但可操作建议只有五份，我们因此主张继续保留范例讨论，同时改进帮助学生从判断问题走向提出建议的提示语。这个决定依据的是可行性和反馈内容，不是范例讨论已经改善学习的证据。我们也不把困难简单归咎于学生能力；提示语是否帮助了这个转化，需要在后续任务里看实际反馈内容是否变化。

## 4. 合成示例｜先稳住编码，再进入效果比较

核心信息：拟申请两个平行班前后测比较；分组方式尚待学校确认，尚未实施。


图表安排：原生可编辑table；不使用原文图片。

| 步骤 | 拟完成的工作 |
| --- | --- |
| 测量 | 独立双编码；据分歧修订规则 |
| 任务 | 改进从问题到修改建议的提示语 |
| 比较 | 申请两平行班前后测；分组待校方确认 |

图注：尚无基线、对照班或学习成绩测验；效果尚待验证。

来源：合成示例材料 · H3：下一步计划与分组待定
预计：60秒

讲稿：

下一步的顺序是先让测量与提示语更可靠，再申请扩大比较。两位研究者要独立编码，核对分歧并修订规则；目前只有共同讨论，不能把这一步当成已经完成。随后根据试用困难修订提示语。我们计划申请在两个平行班进行前后测比较，但学校还没有确认分组方式，因此今天不把它称为随机实验，也不把计划列为研究结果。团队当前的决定可以概括为：保留可行的范例讨论，补上提出建议的支持，再用比较设计验证是否改善反馈。正式比较能支持多强的效果判断，要由最终分组及测量安排决定。
