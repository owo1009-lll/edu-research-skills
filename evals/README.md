# 路由评测

`routes.json` 是 36 条真实场景的请求和预期模块（33 条应触发，3 条与教育研究无关、不应触发）。评测方法：让一个只看到各 skill 的 `name` 和 `description`（以及入口 skill 的路由表）的模型，独立判断每条请求该用哪个模块，再与预期比较。

计分规则：预期模块全部出现且顺序一致即通过；`optional_first` 中的模块（入口 edu-research 作为多步任务的协调者）出现在最前面也算通过；预期为空的请求必须不触发任何模块。

| 日期 | 版本 | 结果 | 备注 |
|---|---|---|---|
| 2026-10-07 | 0.4.0 初稿 | 24/24 | 评测者指出入口描述与各模块重叠、复核描述过窄、样本量估计无归属，随后修改 |
| 2026-10-07 | 0.4.0 | 24/24 | 16、17 两条由入口协调后依次调用两个模块 |
| 2026-10-07 | 0.5.0 | 35/36 | 新增 9 条（外审模拟、返修回复、统计报告审查、摘要、全文一致性）全部正确；第 10 条（编码一致性）只选了 edu-qual，预期还应有 edu-analysis——edu-qual 本身会调用 edu-analysis 的 κ 函数，实际行为不受影响，答案未改。评测者指出 GB/T 7714 格式转换在描述中匹配偏弱，已在 edu-writing 描述中补充 |

修改任何 `description` 后重跑一次。
