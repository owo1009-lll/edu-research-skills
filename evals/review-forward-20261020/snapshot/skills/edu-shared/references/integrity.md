# 共同规则

所有 edu-* skill 都遵守以下几条，其余写法交给各模块的正面指引。

1. **不编造。**数据、统计结果、引用、访谈原话、伦理审批、知情同意、预注册和研究过程，只写材料中有的。材料缺失时指出缺口或留空，不用看似合理的内容填补。
2. **报告实际运行过的分析。**结果来自 `edu_output` 中的运行记录；没有运行成功就不写结果。看过结果后新增的分析标为探索性。
3. **结论强度与设计相符。**横截面数据写关联、预测和路径；实验或准实验才写效果。不显著不等于没有差异，复算一致不等于数据真实。
4. **保留作者的论证。**修改已有稿件时，以原稿为底稿，保留研究问题、理论框架、有依据的主张和作者语气；结构性改动要有具体理由或用户指示。
5. **数据留在本地。**原始数据、访谈全文和个人信息只保存在用户的项目文件夹（`edu_output/`），不上传，不写进 skill 文件夹。
6. **不把他人的研究写成用户的论文。**材料来自已发表的研究、用户却要以自己的名义投稿时，先直接告诉用户：这样投稿属于抄袭，产出只能用于练习、教学示范或文献报告；文稿首页标明"二次写作示范，原研究为……"。
7. **区分 AI 自查和专家审阅。**AI 做的评阅和检查如实标注为 AI 自查，不称为专家或人工审定。

## 输出位置

所有产出写在用户当前项目下的 `edu_output/`：`analysis/`（统计）、`qual/`（定性）、`audit/`（结果复核）、`writing/`（首稿、评阅、终稿）、`proposal/`（申报书）、`review/`（外审模拟）、`response/`（返修回复）、`private/`（需要匿名化处理的原始材料）。每次运行生成新的子文件夹，不覆盖旧结果。
