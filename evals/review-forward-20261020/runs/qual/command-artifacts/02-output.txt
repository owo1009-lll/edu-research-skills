# 教育学原稿审阅

默认交付**原稿对应位置高亮＋原生批注**，保留正文，不自动改写，不另生成审稿报告或意见单。这是 AI 模拟审稿，不是真实的专家评审，不预测录用概率。用户已明确要求改稿时按授权执行，转到 edu-writing 的原稿修改流程，不再次询问已经明确的事项；回复真实外审意见用 edu-response。

## 审阅与标注

1. **读原稿，确定可判断的范围。**根据全文或所给章节、研究类型、语言及已有目标期刊/基金要求审阅。按 [审阅维度](references/review-criteria.md) 同时看贡献、设计、证据、概念、文献、解释与表达，不把定量标准套到质性研究或把混合研究拆成互不相干的两份检查。
2. **核实问题。**需要时运行 `../edu-writing/scripts/check_consistency.py`、`../edu-audit/scripts/check_reporting.py`；它们只提供线索，回到原文和实际材料判断。缺原始数据不能据此断言统计错误，未检索核实不能宣称没有创新或遗漏关键研究。保留有依据的强判断和有效表达，不机械替换动词或每段增加局限。
3. **把意见锚定到必要文字。**一句有多类问题时用主要问题的颜色，在同一批注中分清各项；不要叠加高亮。同一问题在关键位置写主批注，其他位置简短关联。跨章节问题点明相关位置；全文层面的判断可在标题处写总评批注。没有问题的段落无需标注，不设数量配额。

   | 高亮 | 批注性质 | 依据 |
   |---|---|---|
   | 黄色 | 论证、解释或表达建议 | 说明哪项理解或推理需要改善；可选风格偏好不能写成必须遵守的规范 |
   | 红色 | 明确错误或实质矛盾 | 有可核查依据，指出来源及矛盾；稿内数字不一致不等于已确定哪个值真实 |
   | 蓝色 | 待核实、需补材料 | 明确缺什么及它影响哪项判断，不把“未提供”写成“没有做” |

   批注开头标明性质，必要时注明主要/次要；根据问题说明是什么、为何影响理解或结论、怎样处理。备选表达放在批注内，不替换正文。批注语言跟随稿件；新作者标识统一为 **AI 模拟审稿**。
4. **生成原生标注。**读 [文件与锚点](references/annotations.md)，先用 `scripts/annotate_manuscript.py inventory` 建立原文位置，再根据已核实的问题整理内部标注计划，用 `apply` 输出新文件。Word 用原生文字高亮与批注；PDF 用高亮注释及其关联批注，不强行转换格式。已有正文、图表、引文、格式、批注和修订均保留；不在正文插入“【批注】”冒充原生功能。
5. **检查实际文件后交付。**运行 `scripts/annotate_manuscript.py verify`，核对标注与原文对应、保留情况及计划外变动；实际用 Word/可用阅读器打开并检查。条件允许时渲染检查每页的高亮范围、批注、表格和图。结构通过不等于视觉验收。不能可靠定位或生成时，说明具体受限对象，不伪装完成。

仅交付 `原稿名_审稿标注版.docx` 或 `原稿名_审稿标注版.pdf` 与必要的简短说明；原上传文件保持不动。锚点清单、计划及检查日志留在用户项目 `edu_output/review/<新任务文件夹>/`，不作为独立审稿报告附送。没有实质问题时原样保留并如实说明，不制造批注。

## 可选审阅范围

- **独立性**：用户要求多位独立审阅时，使用可用的独立子任务；每位只读原稿、必要材料和自己的任务，内部记录合并去重后仍交付同一份原稿标注版。没有独立运行时不声称已完成独立评阅。
- **申报书**：按 [审阅维度](references/review-criteria.md) 的申报书部分检查选题、论证、设计、基础和可行性；匿名及格式按当年实际模板核对，可调用 `../edu-proposal/scripts/check_proposal.py`。意见仍写入原稿批注。
- **纯文本或无法原生标注的文件**：说明现有文件格式的具体限制。用户提供 DOCX/PDF 后可在原件副本标注；不把重排后的普通文字称为原稿原生批注。

诚信要求见 [共同规则](../edu-shared/references/integrity.md)。只有用户明确要求修改才按其取舍改正文；不能为完成意见补造数据、分析、文献或研究过程。

# 审阅维度

意见的依据和改进作用比条数重要。不把缺材料当作已证实的错误，不把个人文风偏好当作期刊要求。具体批注如何锚定见 [文件与锚点](annotations.md)。

## 共同问题

| 维度 | 依据原稿判断什么 |
|---|---|
| 问题与贡献 | 问题值得回答在哪里；相对最接近研究增加、细化或改变了什么认识；不能只以“首次”或地区新颖性代替论证 |
| 概念与理论 | 概念是否清楚且前后一致；理论是否实际参与问题、比较或解释；作者立场是否有可说明的依据 |
| 文献 | 引文是否支持对应命题，是否超出已读取范围；综述是否比较和综合；核实具体文献后才判断缺少关键研究 |
| 设计与证据 | 研究问题、对象、抽样、时点、比较与分析是否相接；数据质量或伦理记录缺失时指出需要核实的材料 |
| 解释与讨论 | 是否回答问题、解释有依据的模式、处理反例和竞争解释；实际增加的认识是否超越结果复述 |
| 实践判断 | 发现、文献或规范前提如何支持行动；区分已检验措施与应用推论，不统一降低建议力度 |
| 表达与结构 | 句间是否推进，抽象概念能否理解，段落是否承担明确任务；删冗余不删主要发现、推理或重要不确定性 |
| 全文一致性 | 摘要、正文、表图、结论的对象、数值、条件、术语和引用是否一致；局部错误修复不转移到其他章节 |
| 期刊与伦理 | 明确的范围、篇幅、声明及程序要求是否满足；只按已核实的目标期刊或实际研究要求判断 |

## 按研究类型

- **定量**：区分实验、准实验、横断面和纵向设计；核对比较对象、主要结局、实际模型与估计目标。结合效应、区间、单位和教育参照理解结果；不显著不自动是无效或等效。方法是否不合适需依据数据结构及实际处理，不能只凭方法名定错。
- **质性**：核对场景、行动、引文、案例差异、过程和反例怎样支持主题与理论判断；区分参与者理解与研究者解释。民族志、案例与主题分析的目的不同，不统一要求频次、统计显著或同一编码一致性指标；缺少统计检验不意味着应弱化有材料依据的判断。
- **混合**：判断为何需要两类资料、各自回答什么、整合发生在哪个阶段与层级。核对联合展示或讨论是否产生单一资料未提供的认识；不强求一致，也不把访谈当作统计机制验证。不同样本不能假装逐人对应，解释型、探索型、汇聚型不要求同一章节次序。
- **理论**：审阅概念、前提、推导、反例与回应；规范判断有其论证依据，不强迫改成实证假设。

批注用红色前须有具体可核查错误；例如稿内同一个样本的两个总数矛盾可指出，但哪一个总数真实仍可标为待核实。认为文献遗漏时写出已读来源及它改变哪项论证；未完成检索不能直接断言没有创新。

## 申报书

检查选题价值与关键问题、学术史和实际增量、内容与设计的相互支撑、研究基础、周期与资源可行性、预期成果，以及匿名与格式。前期事实和预期目标分开；没有依据的“首次”或计划中的结果不能当作已完成贡献。基金指标、活页匿名要求与篇幅以当年公告和用户提供模板为准。

用户要求独立多视角审阅时，可分别聚焦方法与证据、领域与理论、编辑与表达；不设每人问题配额。内部意见出现分歧时，回到原文核查，必要时在同一批注明确未决事项，不把投票当成事实核验。

# 文件与锚点

在用户项目的新任务目录操作。依赖见本 skill 的 `requirements.txt`：python-docx、lxml、PyMuPDF。脚本直接编辑 Word 文件包、增量保存 PDF；不会先重排整篇稿件。原稿和已有输出不覆盖。

## 操作

```powershell
python -X utf8 <本skill>/scripts/annotate_manuscript.py inventory 原稿.docx --output anchors.json
python -X utf8 <本skill>/scripts/annotate_manuscript.py apply 原稿.docx --plan annotations.json --output 原稿_审稿标注版.docx
python -X utf8 <本skill>/scripts/annotate_manuscript.py verify 原稿.docx 原稿_审稿标注版.docx --plan annotations.json
```

PDF 用相同命令及 `.pdf` 扩展名。未给 `--output` 时自动在原稿旁输出“原稿名_审稿标注版”。实际工作优先显式放入 `edu_output/review/<新任务文件夹>/`。

`anchors.json` 只用于定位，不是审稿判断。助理读原稿和材料后整理 `annotations.json`，不让用户填写技术字段：

```json
{
  "schema_version": 1,
  "comment_language": "zh",
  "source_sha256": "从inventory复制",
  "created_utc": "填写本次实际UTC时间",
  "annotations": [{
    "id": "C1",
    "kind": "error",
    "severity": "major",
    "comment": "这里的样本量与方法部分不同。请对照原始记录核实；当前只确认稿内矛盾。",
    "anchors": [{
      "part": "word/document.xml",
      "paragraph": 3,
      "text_sha256": "该段inventory中的哈希",
      "start": 8,
      "end": 10,
      "quote": "52"
    }]
  }]
}
```

数值仅演示格式，不是可套用的原文位置。索引为 **0 起始**，字符范围左闭右开，Word 段落包含表格内段落。`quote` 必须等于该段对应范围；先核对原文再生成，不靠全文搜索第一处同名句子。

- 新计划用 `comment_language` 指定批注语言：英文稿为 `en`，中文稿为 `zh`；批注正文也使用相同语言。此字段控制自动添加的性质和严重程度标签，不翻译正文。未指定时仅为兼容历史计划沿用中文标签。
- `kind`：`improvement` 黄色、`error` 红色、`verify` 蓝色。`severity` 可省略，或 `major`/`minor`。批注按所选语言自动加性质、可选严重程度和 ID，作者按要求统一为“AI 模拟审稿”；正文内容不插入标签。
- Word 每条批注对应一个段落内范围，可跨普通文字 run（例如局部加粗）。跨章节意见在批注文字中给位置与 ID，不扩大高亮到整篇。
- PDF 锚点用 `page`（1 起始）、`line`（0 起始）、`text_sha256`、`start`、`end`、`quote`；字段从 inventory 的对应行取。一个批注可有同一页多行锚点；脚本支持旋转文字。跨页采用相关批注并互相指向。
- 同一位置的新标注重叠会拒绝生成。先合并为主要颜色的一条意见，再在评论中解释不同问题。零批注可正常输出，不需为了通过检查制造问题。

## 保留与验证范围

Word 仅增加所需原生高亮、批注及关联。检查器比较预期文件包，并在去除新增标记后归一化文字 run 的拆分，再核对正文结构和样式；其他图片、引文字段、已有批注和修订部件保留。PDF 核对原有对象及内容流，仅允许页注释列表增加；核对原有注释、新批注和字符坐标，并在隔离副本中移除注释数组后比较每页渲染。两者均可发现计划外的文本、数据或对象变动。

这些检查验证**原件保留和标注计划一致性**，不证明评论判断正确。需另读评论与来源，实际打开交付文件。Word 可用 `../edu-writing/scripts/render_word.ps1` 渲染正文及高亮；评论内容和精确范围还应在 Word 中检查，或使用带批注的导出方式。缺少 Word/LibreOffice 时明确尚未完成实际打开或视觉检查。

## 明确限制

- 当前 Word 自动锚定限主文/表格中的普通文字。已有超链接、域、图片、修订、文本框保持不变；直接锚定其内部或跨越非文字对象会拒绝，不擅自拆开。可在紧邻且能明确指认问题的普通文字处批注并注明对象；没有准确替代锚点时说明该处尚未标注。页眉、脚注、文本框和修订中的目标不宣称已覆盖。
- 已有高亮的位置不覆盖；新问题可在邻近精确位置批注关联。数字签名文档不修改，避免声称签名仍有效。
- PDF 需要可提取文字层。扫描件未实现 OCR 锚定，不把坐标猜测当作精确文字定位；加密或签名 PDF 需可处理的工作副本。PDF 高亮本身携带作者和批注内容，查看器点击高亮即可读到，不要求正文另外出现文字框。
- 生成失败会给出具体对象及位置，不交付半成品。不把普通文本报告当成已完成的原生批注。

旧 `check_review.py` 与 `report-format.md` 仅保留历史报告兼容，不属于默认流程。

# 共同规则

所有 edu-* skill 都遵守以下几条，其余写法交给各模块的正面指引。

1. **不编造。**数据、统计结果、引用、访谈原话、伦理审批、知情同意、预注册和研究过程，只写材料中有的。材料缺失时指出缺口或留空，不用看似合理的内容填补。
2. **报告实际运行过的分析。**结果来自 `edu_output` 中的运行记录；没有运行成功就不写结果。看过结果后新增的分析标为探索性。
3. **结论强度与设计相符。**横截面数据写关联、预测和路径；实验或准实验才写效果。不显著不等于没有差异，复算一致不等于数据真实。
4. **保留作者的论证。**修改已有稿件时，以原稿为底稿，保留研究问题、理论框架、有依据的主张和作者语气；结构性改动要有具体理由或用户指示。
5. **数据留在本地。**原始数据、访谈全文和个人信息只保存在用户的项目文件夹（`edu_output/`），不上传，不写进 skill 文件夹。
6. **不把他人的研究写成用户的论文。**材料来自已发表的研究、用户却要以自己的名义投稿时，先直接告诉用户：这样投稿属于抄袭，产出只能用于练习、教学示范或文献报告；文稿首页标明"二次写作示范，原研究为……"。
7. **区分 AI 自查和专家审阅。**AI 做的评阅和检查如实标注为 AI 自查，不称为专家或人工审定。

## 输出位置

所有产出写在用户当前项目下的 `edu_output/`：`analysis/`（统计）、`qual/`（定性）、`audit/`（结果复核）、`writing/`（首稿、评阅、终稿）、`proposal/`（申报书）、`review/`（外审模拟）、`response/`（返修回复）、`private/`（需要匿名化处理的原始材料）。每次运行生成新的子文件夹，不覆盖旧结果。
